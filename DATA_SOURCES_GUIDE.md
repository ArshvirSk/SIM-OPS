# 📊 Data Sources & Calculations Guide

## How Every Value is Generated

This guide explains where each metric, prediction, and value comes from in the SIM-OPS dashboard.

---

## 🎯 **KPI Cards (Business Impact Section)**

### 1. **Monthly Revenue**

**Current Value:**
- **Source:** Stripe API or Mock Data
- **Calculation:** `SUM(active_subscriptions.mrr)`
- **Query:** Aggregates all active subscription monthly recurring revenue
- **Refresh:** Real-time via Supabase subscriptions

**Predicted Value:**
- **Source:** ML Revenue Forecaster
- **Model:** Time-series analysis (ARIMA/Prophet)
- **Inputs:** Historical MRR, churn rate, growth trends
- **Calculation:** `current_mrr * (1 + growth_rate - churn_rate)`

**Change Percentage:**
- **Formula:** `((current - predicted) / predicted) * 100`
- **Color:** Green if positive, Red if negative

---

### 2. **Active Customers**

**Current Value:**
- **Source:** Database `customers` table
- **Calculation:** `COUNT(*) WHERE status = 'active'`
- **Query:**
  ```sql
  SELECT COUNT(*) FROM customers WHERE status = 'active'
  ```

**Predicted Value:**
- **Source:** Calculated from signup rate and churn
- **Formula:** `current_customers + (signup_rate * 30) - (churn_rate * current_customers)`
- **Inputs:** 
  - Signup rate: Average new customers per day
  - Churn rate: Percentage of customers leaving

**Change Percentage:**
- **Formula:** `((current - predicted) / predicted) * 100`

---

### 3. **Churn Rate**

**Current Value:**
- **Source:** Calculated from customer cancellations
- **Formula:** `(churned_customers_this_month / total_customers_start_of_month) * 100`
- **Query:**
  ```sql
  SELECT 
    (COUNT(*) FILTER (WHERE status = 'churned' AND churned_at >= date_trunc('month', CURRENT_DATE)) * 100.0) / 
    COUNT(*) FILTER (WHERE created_at < date_trunc('month', CURRENT_DATE))
  FROM customers
  ```

**Predicted Value:**
- **Source:** ML Churn Predictor
- **Model:** XGBoost classifier
- **Inputs:** Customer features (tenure, support tickets, usage, payment history)
- **Calculation:** Aggregates individual customer churn probabilities

**Threshold Monitoring:**
- **Alert Trigger:** Churn rate > 3%
- **Severity:** HIGH if > 3%, CRITICAL if > 4%
- **Action:** Sends Slack/Email alert, triggers retention campaign

**Change Percentage:**
- **Formula:** `((current - predicted) / predicted) * 100`
- **Note:** Lower is better (isNegativeGood = true)

---

### 4. **Active Alerts**

**Current Value:**
- **Source:** Generated by Monitoring Agent
- **Calculation:** `COUNT(*) FROM agent_decisions WHERE severity IN ('high', 'critical') AND resolved = false`
- **Triggers:**
  - KPI threshold violations (churn > 3%, revenue deviation > 5%)
  - Anomaly detection (unusual patterns)
  - High-risk customers (churn probability > 80%)

**Change Percentage:**
- **Formula:** `((current - previous_period) / previous_period) * 100`
- **Period:** Compared to previous day

**Alert Types:**
- **Monitoring Agent:** KPI deviations
- **Prediction Agent:** High-risk customers
- **Feedback Agent:** Model retraining needed

---

### 5. **Active Agents**

**Current Value:**
- **Source:** Database `agents` table
- **Calculation:** `COUNT(*) WHERE status IN ('active', 'processing')`
- **Query:**
  ```sql
  SELECT COUNT(*) FROM agents WHERE status IN ('active', 'processing')
  ```

**Total Agents:** 6
1. Monitoring Agent
2. Prediction Agent
3. Decision Agent
4. Action Agent
5. Reporting Agent
6. Feedback Agent

**Status Values:**
- `active`: Agent is running and ready
- `processing`: Agent is currently executing
- `idle`: Agent is paused
- `error`: Agent encountered an error

---

### 6. **Automation Rate**

**Current Value:**
- **Source:** Calculated from agent decisions
- **Formula:** `(automated_actions / total_decisions) * 100`
- **Query:**
  ```sql
  SELECT 
    (COUNT(*) FILTER (WHERE workflow_triggered = true) * 100.0) / COUNT(*)
  FROM agent_decisions
  WHERE created_at >= CURRENT_DATE
  ```

**What Counts as Automated:**
- Retention campaigns triggered
- Workflows executed
- Notifications sent
- Actions taken without human approval

**Goal:** Higher is better
- **Good:** > 80% (most decisions automated)
- **Average:** 60-80% (some manual intervention)
- **Low:** < 60% (too much manual work)

## 🤖 **Agent Cards**

### Agent Status
- **Source:** `agents` table, `status` column
- **Values:** active, idle, processing, error
- **Update:** Real-time via Supabase subscriptions

### Last Action
- **Source:** `agents.last_action` or latest `agent_decisions.output`
- **Query:**
  ```sql
  SELECT output FROM agent_decisions 
  WHERE agent_id = ? 
  ORDER BY created_at DESC 
  LIMIT 1
  ```
- **Display:** First 60 characters

### Actions Today
- **Source:** `agents.actions_today` column
- **Calculation:** Incremented each time agent makes a decision
- **Reset:** Daily at midnight

## 📈 **Churn Risk List (Deep Insights Tab)**

### Customer Churn Probability
- **Source:** ML Prediction Agent
- **Model:** XGBoost classifier (86.94% accuracy)
- **Training Data:** Kaggle Telco Churn dataset
- **Features Used:**
  - Tenure (months as customer)
  - Support tickets (count)
  - Usage metrics (logins, API calls)
  - Payment history (late payments, failed charges)
  - Contract type (monthly, annual)
  - Subscription tier

**Calculation Process:**
1. Fetch customer data from database
2. Extract features using `MLDataPipeline.extractChurnFeatures()`
3. Validate features
4. Send to ML service: `POST http://localhost:8000/predict/churn`
5. Receive probability (0-100%)
6. Store in `ml_predictions` table

**Risk Levels:**
- **High:** > 80% probability
- **Medium:** 60-80% probability
- **Low:** < 60% probability

**Actions Triggered:**
- High risk (>80%): Retention campaign, account manager notification
- Medium risk (60-80%): Monitoring, engagement campaign
- Low risk (<60%): Standard monitoring

## 🔍 **Anomaly Detection**

### Anomaly Score
- **Source:** ML Anomaly Detector
- **Model:** Isolation Forest
- **Inputs:**
  - Transaction patterns
  - Login frequency
  - API usage
  - Support ticket volume

**Calculation:**
1. Fetch customer activity data
2. Calculate baseline (30-day average)
3. Compare current to baseline
4. Anomaly score = deviation from baseline
5. Score > 0.8 = anomaly detected

**Types of Anomalies:**
- **Usage Spike:** Sudden increase in API calls
- **Usage Drop:** Sudden decrease in logins
- **Transaction Anomaly:** Unusual payment patterns
- **Support Spike:** Sudden increase in tickets

---

## 💰 **Revenue Forecast**

### Forecast Values
- **Source:** ML Revenue Forecaster
- **Model:** Time-series analysis (ARIMA or Prophet)
- **Inputs:**
  - Historical MRR (last 12 months)
  - Churn rate trends
  - Signup rate trends
  - Seasonal patterns

**Calculation:**
1. Fetch historical revenue data
2. Train time-series model
3. Generate 4-week forecast
4. Apply confidence intervals (80%, 95%)
5. Adjust for predicted churn

**Confidence Intervals:**
- **80% CI:** Likely range (darker band)
- **95% CI:** Possible range (lighter band)

## 📝 **Agent Activity Log**

### Log Entries
- **Source:** `agent_decisions` table
- **Query:**
  ```sql
  SELECT * FROM agent_decisions 
  ORDER BY created_at DESC 
  LIMIT 50
  ```

**Fields:**
- **Agent:** Which agent made the decision
- **Decision:** What was decided
- **Reasoning:** Why the decision was made
- **Output:** What action was taken
- **Severity:** low, medium, high, critical
- **Confidence:** 0-100% (model confidence)
- **Timestamp:** When the decision was made

## 🗄️ **Database Tables**

### Key Tables:

**`customers`**
- Stores customer data
- Fields: id, email, status, created_at, churned_at, mrr, tenure, support_tickets

**`agents`**
- Stores agent configuration and status
- Fields: id, name, role, status, last_action, actions_today

**`agent_decisions`**
- Stores all agent decisions
- Fields: id, agent_id, input, reasoning, output, severity, confidence, workflow_triggered, created_at

**`ml_predictions`**
- Stores ML model predictions
- Fields: id, customer_id, prediction_type, prediction_data, confidence, created_at

**`activity_logs`**
- Stores system activity
- Fields: id, type, source, message, metadata, created_at

**`workflows`**
- Stores workflow definitions and status
- Fields: id, name, trigger, status, last_run, success_count

## 🧮 **Calculation Examples**

### Example 1: Churn Rate Calculation

**Scenario:**
- Start of month: 1,000 customers
- End of month: 960 customers
- Churned: 40 customers

**Calculation:**
```
Churn Rate = (40 / 1,000) × 100 = 4.0%
```

**Result:** 4.0% churn rate
**Alert:** CRITICAL (exceeds 3% threshold)
**Action:** Retention campaign triggered

---

### Example 2: Automation Rate Calculation

**Scenario:**
- Total decisions today: 150
- Automated actions: 120
- Manual interventions: 30

**Calculation:**
```
Automation Rate = (120 / 150) × 100 = 80%
```

**Result:** 80% automation rate
**Status:** GOOD (target is >80%)

---

### Example 3: Revenue Prediction

**Scenario:**
- Current MRR: $305,000
- Growth rate: 5% per month
- Churn rate: 4%
- Net growth: 1% (5% - 4%)

**Calculation:**
```
Predicted MRR = $305,000 × (1 + 0.01) = $308,050
```

**Result:** $308K predicted MRR
**Change:** +1% vs current
